# Dispute signature v2

**Status:** Normative · **Domain tag:** `lafiya.attestation.dispute.v2` · **Threat:** T-152

`attestation-registry::dispute_attestation` accepts a patient dispute only with a valid
ed25519 signature over the message defined here. The message ties the signature to one
network, one contract instance, one record, one signer and one nonce, and gives it an expiry.

## Message

```
message = sha256(
    "lafiya.attestation.dispute.v2"   // 29 ASCII bytes, no terminator
 || network_id                        // 32 bytes: sha256(network passphrase)
 || xdr(contract)                     // ScVal::Address XDR of the registry contract (40 bytes)
 || record_hash                       // 32 bytes
 || xdr(signer)                       // ScVal::Address XDR of the `signer` argument
 || signer_key                        // 32-byte ed25519 public key
 || be64(nonce)                       // u64, big-endian
 || be64(expires_at)                  // u64 unix seconds, big-endian
)
signature = ed25519_sign(signer_secret, message)   // signs the 32-byte digest
```

`xdr(address)` is the XDR encoding of `ScVal::Address`. Contracts encode as
`00000012 00000001 || contract_id`. Accounts encode as `00000012 00000000 00000000 || ed25519_key`.
Soroban gives the same bytes from `Address::to_xdr`, and `@stellar/stellar-sdk` from
`Address.fromString(..).toScVal().toXDR()`.

## Contract checks

`dispute_attestation(signer, signer_key, record_hash, nonce, expires_at, signature)`:

1. The contract is not paused.
2. `ledger.timestamp <= expires_at`, otherwise `DisputeExpired` (34).
3. `(signer_key, nonce)` hasn't been used yet, otherwise `DisputeNonceUsed` (35).
4. The existing per-signer duplicate check and per-record bound still apply.
5. `ed25519_verify(signer_key, message, signature)` succeeds, otherwise the host traps.

Wallets should use a random 64-bit nonce or a per-key counter, and an expiry of minutes to
hours.

## v1

v1 (`record_hash` XOR one constant byte, with no network or contract binding) has been removed
without a migration flag: no deployed network has recorded a dispute, so there are no v1
disputes to keep verifying.
